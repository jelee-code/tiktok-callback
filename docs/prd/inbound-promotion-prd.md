## 1. 배경 및 목표

### 1.1 배경 [확정]
- 기간 내 입고량 목표 **총 31만 장** = baseline 약 22만 장 + **순증 약 10만 장**.
- 순증분은 **중간진입(월 100~299장)·중간핵심(월 300~499장)** 세그가 담당한다고 보고 설계함.
  - 근거: 두 세그의 프로모션 반응도(lift)가 각각 ×2.2, ×1.9로, 라이트·상단 세그(×1.0)보다 높음.
- 지급 방식은 **구간별 현금 보상 + 구간별 선착순 인원 제한**으로 확정함.
  - 처음에는 "애정도(개인 성장 서사)"와 "선착순(경쟁)"이 서로 다른 서사를 요구해 부딪혔음. 구간명을 **장수 기준의 중립적 이름(100장/200장/300장/500장/1,000장)**으로 바꿔 이 충돌을 풀었고, 선착순 방식은 그대로 유지함.

### 1.2 목표
| 구분 | 지표 | 목표 |
|---|---|---|
| Primary | 프로모션 기간 총 입고 장수 | **≥ 310,000장** |
| Primary | 예산 집행액 | **≤ 7,000,000원** (설계치 6,875,000원) |
| Secondary | 중간진입 세그 전환율 | 18.3% (자연전환 8.3%) |
| Secondary | 중간핵심 세그 전환율 | 18.2% (자연전환 9.6%) |
| Guardrail | 프로모션 관련 CS 문의 건수 | 기준치 TBD (프로모션 전 2주 평균 대비 모니터링) |
| Guardrail | 마감 이후에도 구간 조건을 채운 셀러 비율 | 모니터링 (캡 조정·후속 프로모션 판단 근거) |

### 1.3 Non-goals (이번 범위 제외)
- 애정도·등급 같은 개인 성장형 서사/UI
- 라이트(20~99장) 세그 전용 보상 구간 (자연전환만 기대)
- 원본 A안·B안 로직 (브리프에 상세 내용이 없어 제외)

| 세그 (월 입고량) | 풀 | 자연전환(2주) | lift | 목표 전환율 | 목표 전환(명) | 건당 인당(장) | 총 기여(장) |
|---|---|---|---|---|---|---|---|
| 라이트(20~99) | 11,434 | 11.0% | ×1.0 | 11.0% | ~1,300 | 38 | ~49,400 |

| **합계** | 16,992 | | | | **~2,278** | | **~316,500** |

- **풀**: 최근 6개월 중 입고가 가장 많았던 달이 해당 구간에 속하는 셀러 수(실측)
- **자연전환(2주)**: 프로모션이 없어도 그 2주 안에 입고할 비율 = 2026-06 실측 재활성률 × 0.6(가정)
- **lift**: 프로모션이 전환율을 끌어올리는 배수(가정)
- **목표 전환(명)** = 풀 × 목표 전환율 / **총 기여** = 목표 전환 × 건당 인당

> 개발 요구: 시스템은 셀러별 **세그 라벨**(위 정의 기준, 프로모션 시작 시점 스냅샷)을 저장해야 함. 성과 분석(세그별 전환율, lift 검증)에 필요함. 세그 라벨은 **참여 자격을 제한하지 않음** (구간 달성은 모든 셀러에게 열려 있음).

## 3. 보상 정책

### 3.1 구간별 보상표 [확정]

| 구간 | 조건(기간 내 입고 장수) | 메인 타깃 | 전환자수(풀) | **선착순 캡(실수혜자)** | 보상 | 구간 예산 | 총기여 장수 |
|---|---|---|---|---|---|---|---|
| T1 | 100장 | 중간진입 하위 | 460 | **250명** | 8,000원 | 2,000,000원 | 64,400 |
| T2 | 200장 | 중간진입 상위 | 307 | **150명** | 15,000원 | 2,250,000원 | 63,600 |
| T3 | 300장 | 중간핵심 | 140 | **80명** | 20,000원 | 1,600,000원 | 56,000 |
| T4 | 500장 | 대량 | 45 | **25명** | 25,000원 | 625,000원 | 30,600 |
| T5 | 1,000장 | 최상위+슈퍼 | 26 | **10명** | 40,000원 | 400,000원 | 52,400 |
| **합계** | | | **978** | **515명** | | **6,875,000원** | **267,000** |

### 3.2 예산 검증
- (250×8,000)+(150×15,000)+(80×20,000)+(25×25,000)+(10×40,000) = **6,875,000원**
  - 브리프의 "6,880,000원(~688만)"은 반올림 값임. 정확한 값은 6,875,000원이고 상한까지 **125,000원** 여유가 있음.
- **예산 안전장치**: 구간마다 `지급 인원 ≤ 캡`이 시스템에서 강제되므로 최대 지출은 캡 × 보상액의 합(6,875,000원)을 넘을 수 없음. 이 불변식은 **4.4 1인 1구간 원칙**을 어떻게 결정하든 유지되어야 함.

### 3.3 설계상 핵심 가정 (리뷰 필요)
- 총기여 267,000장은 **실수혜자(515명)가 아니라 전환자 풀(978명)** 기준으로 계산됨. 즉 조건을 채웠지만 선착순에서 밀린 **약 463명(47%)도 입고한다**고 가정한 값임.
- 267,000장(T1~T5)에 라이트 자연전환 약 49,400장을 더하면 약 316,400장으로 목표 31만을 넘음. 다만 위 가정이 깨지면(마감을 보고 입고를 멈추면) 목표 달성이 어려움.
- → 이 때문에 **"남은 자리" 실시간 노출과 마감 후 안내 UX(FR-3, FR-4)는 부가 기능이 아니라 KPI 달성에 필요한 핵심 기능**임.

## 4. 정책 규칙 (Business Rules)

### 4.1 입고 장수 카운팅
| ID | 규칙 | 상태 |
|---|---|---|
| BR-1 | 카운팅 대상 기간은 프로모션 시작 ~ 종료 일시(KST)이며, 기간 내 **누적** 장수로 판정함 | [제안] (브리프 7번 미정 항목 "누적 vs 스냅샷" → 누적 권장) |
| BR-2 | 카운팅 시점은 **입고 확정(검수 완료) 시점**으로 함. 신청만 한 건은 제외함 | [제안] |
| BR-3 | 검수 불합격·반송·입고 취소 건은 **차감**함. 순 입고 장수 = 확정 장수 − 취소/반송 장수 | [제안] |
| BR-4 | 카운트는 셀러 계정 단위로 함. 동일인 다계정 판정 기준(사업자번호/실명인증/정산계좌 등)은 TBD | [TBD] |

### 4.2 구간 도달 판정
- BR-5: 셀러의 순 입고 장수가 구간 기준(100/200/300/500/1,000) **이상이 되는 순간** 그 구간에 도달한 것으로 판정함.
- BR-6: 도달 판정은 입고 확정 이벤트가 발생할 때마다 **실시간(이벤트 기반)**으로 수행함. 배치로 처리하지 않음.

### 4.3 선착순 자리 확보
- BR-7: **선착순 순서 = 구간 기준을 처음 넘은 입고 확정 이벤트의 타임스탬프 순서**. 동시에 들어온 요청은 DB 트랜잭션 커밋 순서로 결정함 (5.2 참고).
- BR-8: 구간별 `확보 인원 < 캡`일 때만 자리를 확보함. 캡에 도달하면 해당 구간은 즉시 **마감** 상태로 바뀜.
- BR-9: 마감 이후 조건을 채운 셀러는 **대기 순번**을 기록함(자리 반환 시 승계 대상, BR-13).

### 4.4 1인 1구간 원칙 — ⚠️ 결정 필요
브리프에서 한 셀러가 여러 구간에서 보상을 받을 수 있는지 정해지지 않았음. 보상표는 구간마다 메인 타깃이 다르고 인원이 겹치지 않게 짜여 있으므로 **1인 1구간(최고 구간 1회 지급)**이 설계 의도에 맞음.

| 옵션 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. 최고 구간 1회 + 상향 이동** (권장) | 상위 구간 자리를 확보하면 하위 구간 자리를 반환함(반환된 자리는 대기자 승계 또는 재오픈) | 메인 타깃별 인원 배분이 유지됨. 상위 도전 동기가 유지됨 | 남은 자리 수가 늘기도 함 → 안내 문구 필요. 지급은 종료 후 확정해야 함 |
| B. 최초 확보 구간 고정 | 처음 확보한 구간으로 확정함. 상위 도달해도 이동 불가 | 구현이 단순하고 즉시 지급 가능 | 100장 확보 후 더 입고할 동기가 사라짐 → 순증 목표와 충돌 |
| C. 구간별 중복 지급(누적) | 도달한 모든 구간에서 각각 지급함 | 상위 셀러에게 강한 동기 | 대량 셀러가 하위 구간 자리를 차지해 **중간진입 타깃 자리가 밀려남**. 설계 의도와 어긋남 |

- BR-10 [제안·옵션 A]: 셀러는 동시에 **하나의 구간 자리만** 보유함.
- BR-11 [제안·옵션 A]: 상위 구간에 도달했을 때 그 구간에 자리가 있으면 상위 자리를 확보하고 하위 자리를 반환함. 상위 구간이 마감이면 하위 자리를 유지하고 상위 구간 대기 순번에 등록함.
- BR-12 [제안]: 구간 자리 이동과 반환은 **하나의 트랜잭션**으로 처리함 (상위 확보가 실패하면 하위 자리를 유지).

### 4.5 자리 반환·승계
- BR-13: 자리가 반환되면(상향 이동, 반품 차감으로 기준 미달, 어뷰징 판정) 해당 구간 **대기 1순위**가 조건을 계속 충족하는 경우 자동 승계함. 대기자가 없으면 잔여 자리가 1 늘어남.
- BR-14: 반품·취소 차감으로 기준에 못 미치게 되면 자리를 **즉시 회수**함. 이후 다시 기준을 넘으면 그 시점 기준으로 재판정함(앞서 확보했던 순번은 되살리지 않음). [제안]

### 4.6 지급
- BR-15: 지급 수단은 브리프에서 "현금"으로 기재되었으나 현금/포인트/쿠폰 중 최종 결정 필요. [TBD]
- BR-16 [제안]: **기간 종료 후 확정 → 일괄 지급**. 이유: 옵션 A의 상향 이동, 반품 차감, 어뷰징 검수를 반영하려면 종료 후 최종 확정이 필요함. 확정 기준 시점 = 종료 시각 + 반품·검수 유예기간(예: D+7, TBD).
- BR-17: 지급은 셀러당 1건으로 하고, `(promotion_id, seller_id)` 유니크 제약으로 **중복 지급을 방지**함.
- BR-18: 지급 요청·성공·실패·재시도 이력을 모두 로그로 남김.

## 5. 기능 요구사항 (Functional Requirements)

우선순위: **P0** 런칭 필수 / **P1** 런칭 권장 / **P2** 후속

### FR-1. 셀러별 입고 장수 실시간 집계 — P0
- 입고 확정·취소·반송 이벤트를 받아 프로모션 기간 내 셀러별 순 입고 장수를 갱신함.
- 이벤트는 멱등하게 처리함(같은 입고 건이 중복 수신되어도 한 번만 반영, 입고 건 ID 기준).
- **수용 기준**
  - [ ] 입고 확정 후 **5초 이내**에 셀러 화면의 누적 장수에 반영됨
  - [ ] 같은 이벤트가 두 번 들어와도 장수가 한 번만 증가함
  - [ ] 기간 밖 입고 건은 집계에서 빠짐 (시작·종료 경계는 KST 기준, 경계값 테스트 포함)

### FR-2. 구간 도달 판정 및 선착순 자리 확보 — P0
- 장수가 바뀔 때마다 도달 구간을 다시 계산하고, BR-7~BR-12에 따라 자리를 확보·이동·반환함.
- **수용 기준**
  - [ ] 어떤 동시성 조건에서도 구간별 확보 인원이 캡을 넘지 않음 (부하 테스트: 잔여 1석에 동시 요청 100건 → 1건만 성공)
  - [ ] 한 셀러가 동시에 두 구간 자리를 가지지 않음 (옵션 A 채택 시)
  - [ ] 캡에 도달하는 순간 구간 상태가 `CLOSED`로 바뀌고 마감 시각이 기록됨

### FR-3. '남은 자리 N명' 실시간 노출 (셀러 화면) — P0
- 5개 구간 각각의 **기준 장수 / 보상액 / 남은 자리 / 상태**를 표시함.
- 셀러 본인 진행 상황: 현재 누적 장수, 다음 구간까지 남은 장수, 보유 중인 구간 자리, 대기 순번.
- 갱신 방식: 폴링(권장 10~30초) 또는 SSE/WebSocket. 조회 트래픽은 캐시(예: Redis)로 받고, 잔여 수치는 **최대 30초 지연**까지 허용함.
  - 화면에 "N초 전 기준" 또는 "실시간 집계 중, 실제 잔여와 다를 수 있음"을 표기함 (CS 분쟁 대비).
- 노출 채널·페이지 위치: [TBD] (앱 홈 배너, 입고 신청 화면, 프로모션 전용 랜딩 등 후보)

### FR-4. 상태별 안내 문구 — P0
구간 상태 정의 [제안]:

| 상태 | 조건 | 구간 카드 문구 (예시) |
|---|---|---|
| `OPEN` | 잔여 > 캡의 20% | "100장 입고 시 8,000원 · **남은 자리 187명**" |
| `CLOSING_SOON` | 0 < 잔여 ≤ 캡의 20% (임계치 운영 설정) | "🔥 마감 임박! **남은 자리 12명**" |
| `CLOSED` | 잔여 = 0 | "선착순 마감 (09/30 14:32)" + 대기 안내 |
| `REOPENED` | 마감 이후 반환 발생, 대기자 없음 | "자리가 다시 생겼어요 · 남은 자리 1명" |

셀러 개인 상태별 문구 [제안]:

| 셀러 상태 | 문구 (예시) |
|---|---|
| 미도달 | "지금 **63장** 입고했어요. **37장** 더 넣으면 8,000원!" |
| 구간 자리 확보 | "🎉 200장 구간 자리를 확보했어요! (보상 15,000원, 종료 후 지급)" |
| 자리 확보 + 상위 가능 | "300장까지 **58장** 남았어요. 달성하면 20,000원으로 올라가요" |
| 마감 후 도달(대기) | "아쉽게 200장 구간이 마감됐어요. **대기 3번**으로 등록됐고, 자리가 생기면 자동으로 받을 수 있어요" |
| 자리 회수 | "반품/취소로 입고 장수가 기준보다 적어져 구간 자리가 해제됐어요" |

- 선착순 기준, 마감 시각, 지급 시점, 반품 차감 규칙을 **유의사항**으로 화면과 공지에 항상 노출함 (브리프 리스크 3번 대응).
- 마감 후 도달한 셀러에게 **다음 단계 동기**를 주는 문구를 넣음 (예: 상위 구간 잔여 안내) → 3.3의 "미수혜 전환자도 입고한다"는 가정을 지키기 위함.

### FR-5. 알림 (푸시/알림톡) — P1
- 구간 자리 확보, 마감 임박(내가 도달 가능한 구간), 대기 승계, 자리 회수 시 알림을 보냄.
- 발송 채널과 문안은 [TBD]. 수신 동의가 필요하면 기존 마케팅 수신 동의를 따름.

### FR-6. 지급 처리 — P0
- 종료 후 확정 배치: 최종 자리 보유자 목록을 만들고 → 어뷰징 검수(FR-8) → 관리자 승인 → 지급 실행.
- 지급 결과(성공/실패/사유)를 저장하고, 실패 건은 재시도하거나 수동 처리함.
- **수용 기준**
  - [ ] 지급 총액이 6,875,000원을 넘으면 실행 자체가 막힘 (하드 가드)
  - [ ] 셀러당 지급 1건 (유니크 제약)
  - [ ] 지급 이력 CSV 추출이 가능함 (정산팀 대사용)

### FR-7. 관리자(CS·운영) 화면 — P0
- **대시보드**: 구간별 캡 / 확보 / 잔여 / 대기 인원 / 상태 / 마감 시각, 총 입고 장수(목표 31만 대비 진척률), 예상 지급액.
- **셀러 조회**: 셀러 ID·닉네임으로 검색 → 누적 장수, 입고·취소 이벤트 타임라인, 구간 자리 이력(확보·이동·반환 시각), 대기 순번, 지급 상태.
  - CS가 "왜 못 받았나요?" 문의에 **타임스탬프 근거**로 답할 수 있어야 함.
- **운영 설정** (권한 필요, 변경 이력 저장): 기간, 구간 기준·보상액·캡, 마감 임박 임계치, 강제 마감/재오픈, 셀러 제외(어뷰징).
  - 캡 상향은 예산 가드(총액 ≤ 7,000,000원) 안에서만 허용함.
- **권한**: 조회(CS) / 설정 변경(운영) / 지급 승인(관리자) 분리.

### FR-8. 어뷰징 방지 — P1 (정책 확정 후 P0 격상 가능)

| 항목 | 요구사항 |
