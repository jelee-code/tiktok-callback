- **컨셉·구간 타이틀: "최애에게 달려가는 레이스" — 최애까지 남은 거리** [확정 · 2026-09-23]

### 3-2. 지급 규칙

- **최종 도달 구간 1개만 지급 (비누적)** [예시 계승]. 예: 320장 입고 후 300장 구간 자리를 확보한 유저는 올리브영 2만원권 1건만 받음 (100·200장 보상은 중복 지급하지 않음)
- **선착순 순서 = 구간 기준 장수를 처음 넘긴 검수 통과 시각** 순 [협의 — §18-②]
- **상위 구간으로 이동**
  - 하위 구간 자리를 가진 유저가 상위 구간 기준을 넘기고, 상위 구간에 자리가 남아 있으면 → 상위 자리로 옮기고 하위 자리는 반환함
  - 상위 구간이 이미 마감이면 → 하위 자리를 그대로 유지하고 상위 구간 대기자로 등록함
  - 반환된 하위 자리는 해당 구간의 대기 1순위에게 자동 승계되고, 대기자가 없으면 "남은 자리"가 1 늘어남
- **자리 회수**: 검수 반려·입고 취소로 차감되어 기준 장수보다 적어지면 자리를 회수함. 이후 다시 기준을 넘기면 그 시점 기준으로 다시 순번을 매김
- **마감 후 도달자**: 보상은 없지만 대기 순번을 부여해, 자리가 반환되면 자동 승계함

### 3-3. 설계상 핵심 가정 (확인 필요)

- 예상 기여 267,000장은 **선착순 수혜자(515명)가 아니라 예상 도달자 전체(978명)** 기준으로 계산된 값임. 즉, 선착순에서 밀린 **약 463명(47%)도 입고를 이어간다**고 가정함
- 이 가정이 깨지면(마감을 보고 입고를 멈추면) 31만 목표 달성이 어려워짐 → **'남은 자리' 노출, 마감 후 안내, 대기 승계는 목표 달성에 필요한 필수 요소**

## 4. 웰컴 쿠폰 (과거 이력 기반 선지급) [예시 계승 · 협의 필요]

[참여하기]를 누르는 순간, 과거 6개월 안에 한 번이라도 아래 기준을 넘긴 이력이 있으면 자동 지급함.

| 과거 6개월 내 단발 입고 이력 | 시작 시 선지급 웰컴 쿠폰 |
|---|---|
| 30~99장 (1회 이상) | 입고 배송비 쿠폰 1매 |
| 100장 이상 (1회 이상) | 입고 배송비 쿠폰 1매 + 출고 배송비 쿠폰 1매 |
| 이력 없음 (신규·라이트 미만) | 지급 없음 |

- 웰컴 쿠폰은 배송비 할인·면제 쿠폰일 뿐이며, **구간 집계용 누적 장수와 선착순 순서에는 전혀 영향을 주지 않음**
- **예산**: 예시 기획서에서 쿠폰·수수료 할인 원가를 약 50만 원으로 잡았음. 구간 기프티콘 622.5만 원에 더하면 약 **672.5만 원으로 상한 700만 원 이내** (기프티콘 예산 수정으로 이전 초과 문제 해소, 여유 27.5만 원) → 운영 방식 결정 필요 (§18-①)
  - (a) 원안대로 운영 (30~99장 / 100장+ 차등)
  - (b) 웰컴 쿠폰 대상 축소 (예: 100장+ 이력자만)
  - (c) 웰컴 쿠폰 제외 (구간 보상만 운영)
- 참고: 20장(관심) 구간이 사라져 라이트 세그(풀 11,434명)는 받을 보상이 없음. 참여 목표 2,200명 중 약 1,300명이 라이트이므로, 웰컴 쿠폰을 빼면 **참여자 수 목표가 흔들릴 수 있음**

## 5. 집계 규칙 [예시 계승 + 선착순 규칙 추가]

- **집계 대상**: 참여 등록 이후, 이벤트 기간 안에 입고 완료(검수 통과)된 장수만 집계함. 신청 단계·배송 중인 건은 빠짐
- **차감**: 검수 반려·입고 취소분은 자동으로 차감함. 차감으로 기준 장수보다 적어지면 선착순 자리도 회수함
- **갱신 주기**: 개인 진행도와 구간별 "남은 자리"를 **준실시간(목표: 검수 통과 후 1시간 이내)**으로 갱신함 [변경]. 페이지에 "OO:OO 기준" 갱신 시각을 표시함
  - 개발 일정상 어렵다면 MVP로 **매일 자정 갱신 + "전일 자정 기준" 표시**를 적용함 (§7-1)
- **선착순 순서**: 구간 기준을 넘긴 검수 통과 시각(서버 기록) 순. 동시각이면 입고 신청 시각이 빠른 순
- **마감**
  - 11/14(토) 17:00까지 신청된 건 중, 11/30까지 검수센터에 도착해 처리 완료된 분만 최종 인정함
  - 따라서 **11/15~11/30 집계 기간에도 선착순 자리는 계속 채워지거나 이동할 수 있음** → 집계중 화면에도 남은 자리를 계속 노출함

| 1 | 유저별 이벤트 기간 입고 완료 장수를 집계·갱신하고, 페이지에 내 진행도로 표시 | 예시 기획서 기준 자정 갱신 | **준실시간(1시간 이내) 갱신 가능 여부.** 불가능하면 자정 배치 (7-1) |

| 3 | 구간별 **'남은 자리 N명' 노출** + 상태(모집중/마감임박/마감) 자동 전환 | 신규 | 갱신 주기 (#1과 같음), 마감 임박 기준값 어드민 설정 |
| 4 | 최근 6개월 최고월 기준 세그 등급(6단계) 자동 분류 — 화면 노출·분석용 | 파악 못함 | 과거 이력 기준 자동 분류 가능 여부 |
| 5 | [참여하기] 클릭 시 과거 6개월 단발 최대 입고 장수 조회 → 웰컴 쿠폰 자동 발급 (유효기간 11/15까지) | 파악 못함 | ① 참여 시점 트리거 발급 ② 6개월 롤링 최대값 조회 (§4 운영 여부 확정 후) |

| 7 | 동일인 다계정 참여로 인한 중복 수령 방지 | 파악 못함 | 동일인 판별 수단 여부. 없으면 지급 전 운영 검수로 대체 |
| 8 | 어드민: 기간·구간·보상·**선착순 인원**·마감 임박 기준 세팅, on/off, **구간별 확보/잔여/대기 현황 조회**, 유저별 자리 이력(확보·이동·반환 시각) 조회, 최종 명단 CSV 추출 | 럭키드로우는 CSV 추출 후 수동 추첨으로 운영 중 | 동일 방식 구성 가능 여부. 선착순 인원 변경 시 예산 상한(700만) 초과 차단 |

### 7-1. 개발 범위 옵션 (11/2 오픈 일정 대응)

| 구분 | MVP (일정 부족 시) | 권장안 |
|---|---|---|
| 진행도·남은 자리 갱신 | 매일 자정 배치 | 준실시간 (1시간 이내) |
| 선착순 확정 | 11/30 검수 마감 후 **검수 통과 타임스탬프 정렬로 최종 확정** (CSV 기반, 운영 검수) | 시스템이 실시간으로 자리 배정·이동·승계 |
| 남은 자리 표시 | "전일 자정 기준 예상 남은 자리" | 실시간 남은 자리 + 마감 시각 |
| 리스크 | 자정 사이 마감 → "남은 자리 있었는데 못 받음" CS 증가 | 동시 처리 구현 난이도 |

→ MVP로 가더라도 **최종 선착순 순번은 검수 통과 타임스탬프로 사후에 정확히 계산할 수 있어** 공정성은 확보됨. 남은 자리 표시의 실시간성만 떨어짐.

### 구성 요소
- **키비주얼 배너**: 프로모션명(TBD, 레이싱 컨셉) + 종료 D-Day 카운트다운 + 한 줄 문구 (예: "입고할수록 최애에게 가까워져요 — 자리 있을 때 달려가세요!")

  - 최애까지 1km(100장) → 500m(200장) → 100m(300장) → 10m(500장) → 최애 앞 0m(1,000장)

  - 내 현재 위치를 트랙 위 러너 아이콘으로 표시 (애니메이션은 선택)
- **다음 구간 진행 바**: "내 입고 172장 · 28장만 더 넣으면 최애까지 500m! 올리브영 1만원권 + 포스타입 5천원권 (남은 자리 43명)"
- **하단 고정 CTA**: 입고 신청하러 가기
- **유의사항**: 집계 기준(검수 통과·차감), 선착순 기준(검수 통과 시각), 갱신 시각, 1인 1구간, 대기 승계, 지급 일정, 세금 안내

## 9. 지급·운영 (어드민) [예시 계승 + 수정]

- 11/30 검수 마감 후 유저별 **최종 확보 구간** 확정 (1인 1구간, 구간별 선착순 인원 이내)
- 어드민에서 지급 명단 CSV 추출: 유저 / 최종 구간 / 선착순 순번 / 확보 시각 / 보상액 / 차감 이력
- 보상은 12/1 발표 후 **일주일 안에 일괄 지급**
- 지급 수단: **기프티콘으로 확정** (구간별 구성은 §3-1). B2B 대량 발송 업체(기프티쇼 비즈·카카오 선물하기 비즈 등)로 확정 명단 CSV 기반 일괄 문자 발송
  - 12/1 확정 후 실제 수혜 인원만큼 구매 (미리 사두지 않음)
  - 권종(포스타입 5천, 올리브영 1만/2만, 네이버페이 5만, 치킨 세트) 발송 업체 판매 여부 사전 확인
  - 참여 시 개인정보 동의에 "경품 발송용 휴대폰 번호" 포함 필수
- 웰컴 쿠폰은 참여 시점에 이미 개별 지급되므로 종료 후 따로 처리할 것 없음

| 남은 자리 표시 지연으로 "자리 있었는데 못 받음" CS | 갱신 시각 표시, 서버 검수 통과 시각을 최종 근거로 삼음, CS용 유저별 자리 이력 조회 |
